## This template: laser-cut box

A finger-jointed box or enclosure cut from one sheet: the customer sets the outer dimensions, the sheet thickness, the laser's kerf and the finger width, toggles the lid, and gets the assembled box in 3D, the cutting layout on the sheet, and the layout as DXF or SVG plus the box as STEP.

- `src/panels.ts` is the geometry that needs no kernel: which panels the box has and the joint on each edge (`panelSpecs`), the outline of a panel as a closed polygon with the fingers, the slots and the kerf compensation worked in (`outlineFor`; `tidy` then removes repeated points and zero-width spikes cyclically, a spike being where the walk goes to a point and straight back, as happens where an edge ends flush and the next starts with a slot), the lid's finger-hole handle where the lid has room for it with its clearance to the fingers (`handleFor`, `HANDLE`, `slotArea`), the parts with their sizes (`partsFor`), and the row packing onto the sheet (`layoutParts`, `partsOverlap`). It is pure, so a change to the joint logic is testable by reading the points.
- `src/model.ts` is the kernel side. `buildModel(occt, params)` turns every outline into a planar face on the ground plane (the lid's handle as a hole in it, a rectangle rounded to a stadium, turned to run against the outline with `faceWithHole` because the kernel cuts only from an inner wire running the other way), translates a copy onto the sheet for the layout (the DXF is written from that face), extrudes that copy into a slab lifted one millimetre above the ground for the layout view (`LAYOUT_LIFT`, so the parts and the sheet outline never fight the ground plane for pixels), and extrudes another and rotates and moves it into its place in the assembled box. Faces are made on the ground plane (X and Z) because that is the plane `occt.io.shapeToDxfPaths` flattens into a drawing.
- `src/exports.ts` writes the layout SVG straight from the outlines, the handle as a rounded rectangle. DXF and STEP come from the kernel in `src/main.ts` (`shapeToDxfPaths`, `dxfPathsWithLayer`, `dxfCreate`; `makeCompound`, `saveShapeSTEP` converted to Z-up).
- `src/ui.ts` renders the panel with plain DOM; `src/main.ts` is the wiring: scene, kernel, debounced rebuilds, the two views, the downloads, one birch plywood material per panel under a room environment with the laser's brown on the cut edges. `cameraOptions` gives the orbit camera explicit distance limits from the scene size and leaves its sensitivities at their base values: the engine's defaults scale zoom and pan by the scene size although both already follow the camera's distance, so a scene this large would jump a third of the way in per wheel notch.
- `scripts/smoke.ts` builds the default box and three variants (no kerf, no lid, tall) on the in-process kernel and prints one JSON line with `template`, `params` and, per case, `parts`, `fingers` per panel, `dxfPaths` per panel, `layout` (fits, used width and height), `handle`, `materialVolume` and `jointsClosed`. It exits 1 when the part count is not five or six, a part is not one planar face, a part yields no DXF path, two parts overlap on the sheet, the assembled box does not span the declared length by height by width, or, with the kerf at zero, the panels do not tile the hollow box: their volumes must add up to the outer block minus the cavity and minus the handle (`hollowBox` in the output) and no two panels may share any volume, which together mean every finger fills its slot and nothing is doubled. The kernel is loaded in-process from `node_modules`, the same WebAssembly the browser runs inside a worker; its content-hashed `.wasm` is found beside the loader rather than spelled out.

Commands:

- `npm run dev` serves the app at http://localhost:5173
- `npm run build` typechecks and bundles for production; `npm run typecheck` and `npm run lint` run alone as well
- `npm run smoke` typechecks, lints, then builds the cases headlessly and prints the summary line. The smoke script types the in-process kernel as the same `Occt` the browser code sees, through one `inProcess` cast, and awaits every call, so `buildModel` runs exactly as it does in the browser and `scripts/` is typechecked with the rest.

The joint rule: a `fingers` edge grows fingers one thickness beyond the panel's nominal edge, the `slots` edge it meets is cut one thickness deep at the same positions, and each edge has an odd number of segments (at least three) near the finger width, so both ends of an edge are the same kind and the pattern reads the same from either panel. The bottom and the lid have fingers on all four edges; the front and back have fingers on their vertical edges; the sides have slots everywhere. Kerf compensation moves every outline outward by half the kerf, widening fingers and narrowing slots by that much, so the cut part comes out at the nominal size. Change the rule in `panelSpecs` and `outlineFor` only, then run the smoke: the tiling check is what proves the joints still close.
