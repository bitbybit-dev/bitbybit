## This template: product configurator

A parametric planter with its own form, a live price and downloads, the way a storefront page would present a made-to-measure product. Everything the customer sees comes from the geometry: the price is computed from the solid's measured volume and surface area, so a change to the model changes the quote by itself.

- `src/model.ts` is the geometry. `buildModel(occt, params)` builds the planter and returns the shape with its volume and surface area: walls that lean inward by a draft angle (`occt.draft.draftAngle` on the side faces of a rounded block, the negative angle being the inward lean), a stepped lip at the rim, the cavity drafted the same way so the wall keeps one thickness, the rim's edges rounded (selected by their height with `getEdgesCentersOfMass`), a recess under the base so the pot stands on a rim, and the drainage holes, all with planes, cylinders and cones so the booleans stay quick. `STYLE` holds those fixed proportions; `taperAngle` eases the lean off on tall narrow pots so the base keeps at least half the top. One kernel limit is worked around on purpose: a drafted block whose corner arcs are under a millimetre makes the hollowing boolean return the outer solid untouched, so corners that small are cut sharp (`SMALLEST_DRAFTED_CORNER`). `PlanterParams` are the customer-facing parameters, `LIMITS` their ranges, `clampParams` the rule that keeps them buildable (a corner radius cannot exceed half the smallest side minus the wall). Every kernel call is awaited, so the same function runs in the browser through the OCCT worker and in Node in-process.
- `src/catalog.ts` is the shop side: materials with a colour, a roughness and a clearcoat for the physically based look, and a price per litre, three presets, and `quoteFor(params, model)`, the price formula. It reads the model's measurements and nothing else, so it is pure and the smoke checks it for every preset.
- `src/ui.ts` renders the panel (presets, sliders, material, quote, export buttons) with plain DOM and calls back on change. It knows the parameter names and limits, not the kernel.
- `src/main.ts` is the wiring: the Three.js scene, Bitbybit, debounced rebuilds that drop stale results, the draw with one physically based material per catalogue material under a room environment, and the STEP, STL and GLB downloads. `cameraOptions` gives the orbit camera explicit distance limits from the scene size and leaves its sensitivities at their base values: the engine's defaults scale zoom and pan by the scene size although both already follow the camera's distance, so a scene this large would jump a third of the way in per wheel notch. STEP and STL come from the OCCT kernel (`occt.io.saveShapeSTEP`, `occt.io.saveShapeStl`, converted to Z-up for CAD tools); GLB comes from Three.js's `GLTFExporter` over the drawn group.
- `scripts/smoke.ts` builds the default planter and every preset on the in-process kernel and prints one JSON line: `template`, `params`, then for `default` and each entry of `presets` the fields `valid`, `faces`, `edges`, `volume`, `surfaceArea` and `price`. It exits 1 when any planter is not a valid solid, has no volume, is not hollow (its volume must be below the block's less the cavity's least possible size), has a bounding box other than the declared width by height by depth (within the rim's radius, because OpenCascade's box around a fillet surface is loose by up to that), has a quote that is not a positive number, or places a different number of drainage holes than asked. The kernel is loaded in-process from `node_modules`, the same WebAssembly the browser runs inside a worker; its content-hashed `.wasm` is found beside the loader rather than spelled out.

Commands:

- `npm run dev` serves the configurator at http://localhost:5173
- `npm run build` typechecks and bundles for production; `npm run typecheck` and `npm run lint` run alone as well
- `npm run smoke` typechecks, lints, then builds every preset headlessly and prints the summary line. The smoke script types the in-process kernel as the same `Occt` the browser code sees, through one `inProcess` cast, and awaits every call, so `buildModel` runs exactly as it does in the browser and `scripts/` is typechecked with the rest.

To add a parameter: add it to `PlanterParams` and `defaultParams`, give it a range in `LIMITS`, use it in `buildModel`, add a field in `ui.ts`, and if it costs money, price it in `quoteFor`. Then run the smoke and, if the change pins a new fact, assert it there.

Units are centimetres in the model and in the scene; prices are in `CURRENCY` from `src/catalog.ts`. The material and finish rates are illustrative numbers to replace with the shop's own; the formula's structure (base, material by volume, finish by surface, options) is the part worth keeping.
